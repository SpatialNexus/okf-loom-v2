## Release proof requirement

Release capture proof constructs a test-local clean candidate repository from
the exact reviewed primary-worktree candidate files (excluding `.gitignore` and
`.aic/`), commits it with test-local identity, and invokes that candidate's
checked-in runner. The exact candidate explicitly copies and tracks
`scripts/okf_loom/session_authority.py`
so the final release commit includes the authority implementation even when it
is still untracked in the primary worktree before commit. The runner owns a
closure-sealed physical checkout identity;
the public `ROOT` alias is display-only and cannot transfer authority. Immediately
after the commit/tree pair is captured, the entire recursive commit tree is
materialized by exact object ID into one private workspace and its complete
path/OID/hash/mode inventory is verified. `--bundle` is confined to the original
checkout only for admission, then mapped to the same relative tree inside that
workspace. Every later dynamic helper import, revision derivation, build, live
serve executable/cwd, template, asset and bundle consumer is explicitly bound to
that workspace by the access registry; publication re-verifies its inventory.
The checked-in `samples/empty_bundle` is the canonical zero-concept fixture.

Every row above must have an exact test, browser assertion, or final-revision
capture reference before release closure. The capture manifest reports accepted
automated work as **interim evidence** while the human screen-reader session is
pending; `final_release_evidence` remains false until that session is executed
and accepted. Historical screenshots and a dirty-tree manifest are context only,
never committed-release evidence. Browser-owned 200%/400% zoom remains pending
unless its external headed-Chrome driver actually runs; typed `zoom-unsupported`
is truthful diagnostics, not positive proof.
